# 15장. 종합 실습 평가

1장부터 11장까지 배운 Spring Boot, REST API, JPA, Spring MVC, Thymeleaf를 모두 사용하여 **미니 프로젝트**를 구현한다.
이 장의 명세서가 곧 **평가 기준**이다. 명세서에 적힌 대로 동작하는지를 기능별로 확인하여 점수를 매긴다.

## 평가 개요

| 항목 | 내용 |
| --- | --- |
| 프로젝트 주제 | 1인용 할 일 관리 서비스 **My Todo** |
| 수행 시간 | **2시간** |
| 수행 방식 | 개인 |
| 사용 기술 | Spring Boot + REST API + JPA + Spring MVC + Thymeleaf |

| 참고 자료 | 이 교재와 자신의 실습 프로젝트(`hello`). 실습 코드를 복사하여 고쳐 써도 된다. |

## 프로젝트 소개

**My Todo**는 사용자 **한 명**이 자신의 할 일을 등록하고 관리하는 서비스이다. 로그인 기능은 없다.

- 할 일을 등록하고, 목록·상세 화면에서 확인하고, 수정·삭제할 수 있다.
- 할 일을 **완료** 또는 **진행 중** 상태로 바꿀 수 있다.
- 목록에서 제목으로 **검색**하고, 상태별로 **걸러 보고**, **페이지** 단위로 볼 수 있다.
- 같은 기능을 **웹 화면**과 **REST API**로 모두 제공한다.

모든 기능은 다음 요구사항을 지켜 구현한다.

**프로젝트 설정**

| 항목 | 값 |
| --- | --- |
| 프로젝트 | Gradle, Java 25, Spring Boot 4.1.x |
| Group / Artifact | `com.example` / `todo` |
| 기본 패키지 | `com.example.todo` |

| 데이터베이스 | H2 파일 모드: `jdbc:h2:file:./data/tododb` |

**구현 규칙**

| 번호 | 규칙 |
| --- | --- |
| 1 | 테이블은 **DDL 스크립트**(`src/main/resources/db/schema.sql`)로 정의한다. 엔티티로 테이블을 자동 생성하지 않는다. (`spring.jpa.hibernate.ddl-auto=validate`) |
| 2 | **Controller - Service - Repository** 계층으로 나눈다. 트랜잭션은 서비스에서 처리한다. |
| 3 | 컨트롤러는 엔티티를 그대로 응답하거나 모델에 담지 않고 **DTO**를 사용한다. |
| 4 | Thymeleaf 템플릿은 **`data-th-` 형식**으로 작성한다. |
| 5 | 데이터를 바꾸는 화면 요청(등록, 수정, 완료 전환, 삭제)은 **`POST` 폼**으로 보내고, 처리 후에는 **리다이렉트**한다. (PRG 패턴) |

> 공통 요구사항을 지키지 않은 기능(F2 ~ F11)은 해당 기능의 점수에서 **1점을 감점**한다. (기능마다 최대 1점)

**권장 패키지 구조**

```
com.example.todo
├── TodoApplication.java
└── todo
    ├── TodoEntity.java
    ├── TodoRepository.java
    ├── TodoService.java
    ├── TodoForm.java                  ← 화면 폼 객체
    ├── TodoCreateRequest.java         ← API 요청 DTO
```

## 데이터 명세

### todo 테이블

| 열 | 타입 | 제약 조건 | 설명 |
| --- | --- | --- | --- |
| `id` | `BIGINT` | 기본 키, 자동 증가 | 할 일 번호 |
| `title` | `VARCHAR(100)` | `NOT NULL` | 제목 |
| `memo` | `VARCHAR(1000)` | (`NULL` 허용) | 메모 |
| `done` | `BOOLEAN` | `NOT NULL`, 기본값 `FALSE` | 완료 여부 |

### DDL 스크립트

테이블은 다음 DDL로 정의한다. `src/main/resources/db/schema.sql` 파일에 **그대로** 저장하여 사용한다.

```sql
-- 할 일 테이블
CREATE TABLE IF NOT EXISTS todo (
  id    BIGINT        GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,    -- 할 일 번호 (자동 증가)
  title VARCHAR(100)  NOT NULL,                                        -- 제목
  memo  VARCHAR(1000),                                                 -- 메모 (NULL 허용)
  done  BOOLEAN       NOT NULL DEFAULT FALSE                           -- 완료 여부
);
```

`application.properties`에는 다음 설정이 필요하다. (6장)

```properties
# H2 파일 모드
spring.datasource.url=jdbc:h2:file:./data/tododb
spring.datasource.username=sa
spring.datasource.password=

# H2 콘솔
spring.h2.console.enabled=true
spring.h2.console.path=/h2-console

# 애플리케이션이 시작될 때 DDL 스크립트 실행
spring.sql.init.mode=always
spring.sql.init.schema-locations=classpath:db/schema.sql

# Hibernate는 엔티티와 테이블이 맞는지 검사만 한다.
spring.jpa.hibernate.ddl-auto=validate
```

> DDL 스크립트를 고치지 않는다. 엔티티는 이 테이블에 맞춰 작성한다. (`done` 열은 자바의 `boolean`, `memo` 열은 `String`)

## 화면 명세

### 화면 주소

| 화면 / 처리 | 메서드 | 주소 | 처리 후 |
| --- | --- | --- | --- |
| 할 일 목록 | `GET` | `/todos` | |
| 할 일 등록 폼 | `GET` | `/todos/new` | |
| 할 일 등록 처리 | `POST` | `/todos` | 상세 화면으로 리다이렉트 |
| 할 일 상세 | `GET` | `/todos/{id}` | |
| 할 일 수정 폼 | `GET` | `/todos/{id}/edit` | |
| 할 일 수정 처리 | `POST` | `/todos/{id}/edit` | 상세 화면으로 리다이렉트 |
| 완료 전환 처리 | `POST` | `/todos/{id}/toggle` | 목록 화면으로 리다이렉트 |
| 할 일 삭제 처리 | `POST` | `/todos/{id}/delete` | 목록 화면으로 리다이렉트 |

### 목록 화면의 요청 파라미터

`GET /todos`는 다음 요청 파라미터를 받는다. 모두 생략할 수 있다.

| 파라미터 | 값 | 기본값 | 의미 |
| --- | --- | --- | --- |
| `keyword` | 문자열 | 없음 | 제목에 이 문자열이 **포함된** 할 일만 보여 준다. 비어 있으면 검색하지 않는다. |
| `status` | `all`, `active`, `done` | `all` | `all`: 전체, `active`: 진행 중만, `done`: 완료만. 다른 값이면 `all`로 처리한다. |
| `page` | 1 이상의 정수 | `1` | 페이지 번호. 한 페이지에 **5개**씩 보여 준다. |

예: `/todos?keyword=스프링&status=active&page=2` → 제목에 "스프링"이 들어간 진행 중인 할 일의 2페이지

### 공통 레이아웃

모든 화면은 **프래그먼트**(10장)로 만든 공통 헤더와 푸터를 사용한다.

| 영역 | 내용 |
| --- | --- |
| 헤더 | 서비스 이름 "My Todo"(목록 화면 링크), 메뉴: `할 일 목록`, `할 일 추가`, `API 문서`(Swagger UI) |
| 푸터 | 저작권 문장 등 한 줄 |

### 화면별 내용

| 화면 | 표시 내용과 동작 |
| --- | --- |
| 할 일 목록 | 요약 문장 "전체 **N**개 중 **M**개 완료", 검색 폼(제목 검색어 입력, 상태 선택, 검색 버튼), 할 일 표(번호, 제목, 상태, 완료 전환 버튼), 이전·다음 페이지 링크. 제목을 누르면 상세 화면으로 이동한다. 표시할 할 일이 없으면 "할 일이 없습니다."를 표시한다. |
| 할 일 등록·수정 폼 | 제목, 메모 입력. 수정 폼에는 기존 값이 채워져 있다. |
| 할 일 상세 | 제목, 메모(**줄바꿈 유지**), 상태. `목록`, `수정` 링크, `완료 전환`, `삭제` 버튼 |

- 상태는 `done`이 `true`이면 `완료`, `false`이면 `진행 중`으로 표시한다.
- 완료 전환 버튼의 글자는 진행 중이면 `완료`, 완료이면 `되돌리기`로 표시한다.
- 삭제 버튼은 누르면 확인 창(`confirm`)을 띄운다.
- 등록·수정·완료 전환·삭제 후에는 처리 결과 메시지를 리다이렉트된 화면에 한 번 표시한다. (플래시 속성)
- 목록은 **최근에 등록한 순서**(번호 내림차순)로 표시한다.
- 요약 문장의 N, M은 검색·상태 조건과 관계없이 **전체** 할 일의 개수이다.

## REST API 명세

### 공통

| 항목 | 내용 |
| --- | --- |
| 기본 주소 | `/api/todos` |
| 요청·응답 형식 | JSON |
| API 문서 | Swagger UI(`/swagger-ui.html`)에서 모든 API를 확인할 수 있어야 한다. (8장) |

### API 목록

| 기능 | 메서드 | 주소 | 성공 | 실패 |
| --- | --- | --- | --- | --- |
| 할 일 목록 | `GET` | `/api/todos` | `200` | `400`(잘못된 `status`) |
| 할 일 조회 | `GET` | `/api/todos/{id}` | `200` | `404` |
| 할 일 등록 | `POST` | `/api/todos` | `201` | `400`(제목 오류) |
| 할 일 변경 | `PUT` | `/api/todos/{id}` | `200` | `400`, `404` |
| 할 일 삭제 | `DELETE` | `/api/todos/{id}` | `204` | `404` |

### 응답 본문

할 일 한 개(`TodoResponse`)는 다음 형식이다. 목록은 이 객체의 배열이다.

```json
{
  "id": 3,
  "title": "스프링 복습",
  "memo": "8장~11장 다시 읽기",
  "done": false
}
```

### 목록: GET /api/todos

- 모든 할 일을 번호 내림차순으로 응답한다. (페이지를 나누지 않는다.)
- 요청 파라미터 `status`(`all`, `active`, `done`)로 상태별로 거를 수 있다. 생략하면 `all`이다.
- `status`가 이 세 값이 아니면 `400`을 응답한다. (화면과 다르다.)

### 등록: POST /api/todos

```http
POST /api/todos
Content-Type: application/json

{
  "title": "스프링 복습",
  "memo": "8장~11장 다시 읽기"
}
```

- 응답: `201 Created`, `Location: /api/todos/{새 번호}` 헤더, 본문은 등록한 할 일
- `done`은 `false`로 저장한다.
- 제목이 없거나(공백만 있는 경우 포함) 100자를 넘으면 `400`을 응답한다.

### 변경: PUT /api/todos/{id}

```http
PUT /api/todos/3
Content-Type: application/json

{
  "title": "스프링 복습 (수정)",
  "memo": "9장부터 다시 읽기",
  "done": true
}
```

- 응답: `200 OK`, 본문은 변경한 할 일
- 제목, 메모, 완료 여부를 요청 값으로 바꾼다. `done`이 없으면(`null`) 완료 여부는 **바꾸지 않는다.**
- 제목 규칙은 등록과 같다. (`400`)

### 삭제: DELETE /api/todos/{id}

- 응답: `204 No Content` (본문 없음)

| 빌드(컴파일)에 실패한다. | 문법 오류, 없는 클래스를 `import`, 의존성 누락 |

| 제출 파일에 프로젝트가 없거나 압축을 풀 수 없다. | |

- 실행되지 않으면 평가자는 오류 원인만 **최소한으로 고쳐** 실행한 후 나머지 기능을 채점한다. 이때 F1의 "오류 없이 실행"(25점)과 "접속"(10점) 항목은 0점이고, 합계에서 20점을 **추가로** 뺀다.
- 감점 후 총점이 0점보다 작으면 0점으로 한다.
- 실행은 되지만 특정 화면이나 API에서만 오류가 나는 경우는 실행 감점이 아니라, 해당 기능의 채점 기준에 따라 점수를 주지 않는다.

### F4. 할 일 목록과 공통 레이아웃 (4점)

**요구사항**

- 요약 문장 "전체 **N**개 중 **M**개 완료"를 표시한다.
- 표시할 할 일이 없으면 "할 일이 없습니다."를 표시한다.
- 모든 화면에 **프래그먼트**로 만든 공통 헤더와 푸터를 적용한다.

**채점 기준**

| 확인 내용 | 점수 |
| --- | --- |
| 할 일이 최근 등록 순으로 표시되고, 상태가 `완료` / `진행 중`으로 표시된다. | 1 |
| 제목을 누르면 상세 화면으로 이동한다. 할 일이 없으면 안내 문장이 표시된다. | 1 |
| "전체 N개 중 M개 완료"가 실제 개수와 맞게 표시된다. | 1 |
| 모든 화면에 공통 헤더·푸터가 표시되고, `data-th-fragment`와 `data-th-replace`(또는 `insert`)로 구현되어 있다. (코드 확인) | 1 |

### F5. 할 일 상세 (4점)

- 상세 화면에 `목록`, `수정` 링크와 `완료 전환`, `삭제` 버튼(F7)을 둔다.
- 없는 번호로 요청하면 `404`를 응답하고, 직접 만든 **404 오류 화면**(`templates/error/404.html`)을 보여 준다.

**채점 기준**

| 확인 내용 | 점수 |

| 없는 번호로 접속하면 상태 코드가 `404`이다. (개발자 도구로 확인) | 1 |

### F6. 할 일 수정 (5점)

**요구사항**

- `GET /todos/{id}/edit`에서 기존 값이 채워진 수정 폼을 보여 주고, `POST /todos/{id}/edit`로 제목과 메모를 수정한다.
- 등록 폼과 **같은 템플릿**을 사용한다. 화면 제목, 폼을 보낼 주소, 버튼 글자가 등록·수정에 맞게 바뀐다.
- 수정은 JPA **변경 감지**로 처리한다. (서비스에서 `save()`를 호출하지 않는다.)
- 수정 후 상세 화면으로 리다이렉트하여 "할 일을 수정했습니다."를 표시한다.
- 없는 번호의 수정 폼·수정 처리를 요청하면 404 화면을 보여 준다.

**채점 기준**

| 확인 내용 | 점수 |
| --- | --- |
| 수정 폼에 기존 제목과 메모가 채워져 있다. | 1 |
| 등록과 수정이 한 템플릿을 사용하고, 화면 제목·버튼 글자가 각각에 맞게 표시된다. (코드 확인) | 1 |
| 수정 시 입력 값 검증이 적용되고, 오류가 있어도 폼을 보낼 주소가 수정 주소로 유지된다. | 1 |
| 수정하면 값이 바뀌고 상세 화면으로 리다이렉트되어 메시지가 표시된다. | 1 |
| 서비스가 변경 감지로 수정한다. (코드 확인) 없는 번호는 404 화면이 나온다. | 1 |

### F7. 완료 전환과 삭제 (5점)

**요구사항**

- `POST /todos/{id}/toggle`은 완료 여부를 반대로 바꾸고(`진행 중` ↔ `완료`) 목록 화면으로 리다이렉트하여 "상태를 변경했습니다."를 표시한다. 목록과 상세 화면에서 사용한다.
- `POST /todos/{id}/delete`는 할 일을 삭제하고 목록 화면으로 리다이렉트하여 "할 일을 삭제했습니다."를 표시한다.
- 두 기능 모두 `data-th-action`을 사용한 `POST` 폼으로 요청한다. 삭제 버튼은 확인 창을 띄운다.
- 없는 번호로 요청하면 404 화면을 보여 준다.

**채점 기준**

| 확인 내용 | 점수 |
| --- | --- |
| 목록의 완료 전환 버튼을 누르면 상태와 버튼 글자가 바뀌고, "M개 완료" 숫자도 바뀐다. | 1 |
| 상세 화면의 완료 전환 버튼도 동작한다. 처리 후 메시지가 표시된다. | 1 |
| 삭제 버튼을 누르면 확인 창이 뜨고, `취소`하면 삭제되지 않는다. | 1 |
| 확인하면 삭제되고 목록 화면에 메시지가 표시된다. | 1 |
| 두 기능이 `POST` 폼으로 구현되어 있다. (`GET` 링크로 구현하면 0점) | 1 |

### F8. 검색과 상태 필터 (6점)

**요구사항**

- 목록 화면에 검색 폼(`GET` 폼)을 둔다. 제목 검색어 입력 창과 상태 선택(`전체`, `진행 중`, `완료`), 검색 버튼으로 구성한다.
- "목록 화면의 요청 파라미터"의 `keyword`, `status`에 따라 할 일을 거른다. 두 조건을 **함께** 사용할 수 있다.
- 조건에 맞는 할 일은 **데이터베이스에서** 조회한다. (쿼리 메서드 또는 JPQL) 모든 할 일을 조회한 후 자바 코드로 거르지 않는다.
- 검색한 후에도 검색 폼에 검색어와 선택한 상태가 **유지**된다.

**채점 기준**

| 확인 내용 | 점수 |
| --- | --- |
| 제목 검색어로 검색하면 제목에 검색어가 포함된 할 일만 표시된다. | 1 |
| 상태를 `진행 중` 또는 `완료`로 선택하면 해당 상태의 할 일만 표시된다. | 1 |
| 검색어와 상태를 함께 지정하면 두 조건을 모두 만족하는 할 일만 표시된다. | 1 |
| `status`에 잘못된 값(예: `status=abc`)을 주면 전체로 처리된다. (오류가 나지 않는다.) | 1 |
| 검색 후 검색 폼에 검색어와 선택한 상태가 유지된다. | 1 |
| 조건 검색이 쿼리 메서드 또는 JPQL로 구현되어 있다. (코드 확인) | 1 |

### F9. 페이지 나누기 (5점)

**요구사항**

- 목록을 한 페이지에 **5개**씩 보여 준다. 페이지 번호(`page`)는 1부터 시작한다.
- 페이지 단위 조회는 `Pageable`(`PageRequest`)을 사용하여 **데이터베이스에서** 조회한다. (7장, 8장)
- 목록 아래에 `이전`, 현재 페이지 번호, `다음` 링크를 표시한다. 첫 페이지에는 `이전`이, 마지막 페이지에는 `다음`이 없다.
- 페이지 링크는 현재의 `keyword`, `status`를 **유지**한다. (링크 URL 표현식, 10장)

**채점 기준**

| 확인 내용 | 점수 |
| --- | --- |
| 할 일이 6개 이상이면 첫 페이지에 최근 5개만 표시된다. | 1 |
| `다음`, `이전` 링크로 페이지를 이동하면 해당 페이지의 할 일이 표시된다. | 1 |
| 첫 페이지에는 `이전`이, 마지막 페이지에는 `다음`이 표시되지 않는다. | 1 |
| 검색어·상태를 지정한 상태에서 페이지를 이동해도 조건이 유지된다. | 1 |
| 페이지 조회가 `Pageable`로 구현되어 있다. (코드 확인) | 1 |

### F10. REST API: 조회 (5점)

**요구사항**

- `GET /api/todos`: 할 일 목록을 응답한다. `status` 파라미터로 거를 수 있고, 잘못된 값이면 `400`
- `GET /api/todos/{id}`: 할 일 한 개를 응답한다. 없으면 `404`
- 응답은 "응답 본문" 형식의 DTO(`TodoResponse`)로 한다. 엔티티를 그대로 응답하지 않는다.

**채점 기준**

| 확인 내용 | 점수 |
| --- | --- |
| 목록 API가 명세의 JSON 형식(`id`, `title`, `memo`, `done`)으로, 번호 내림차순으로 응답한다. | 1 |
| 응답이 DTO로 구현되어 있다. (코드 확인) | 1 |
| `status=active`, `status=done`으로 거르고, 잘못된 값은 `400`을 응답한다. | 1 |
| 조회 API가 할 일을 `200`으로 응답한다. | 1 |
| 조회 API가 없는 번호에 `404`를 응답한다. | 1 |

**요구사항**

## 평가 절차

평가자는 제출된 프로젝트를 다음 순서로 실행하고 확인한다.

### 1) 준비

1. 압축을 풀고 `data` 폴더가 있으면 **삭제**한다. (깨끗한 데이터베이스에서 시작)
2. `./gradlew bootRun`으로 실행한다. (F1) 실행되지 않으면 평가자가 오류 원인만 최소한으로 고쳐 실행하고, 나머지 기능을 채점한 후 **총점에서 20점을 감점**한다.
3. H2 콘솔([http://localhost:8080/h2-console](http://localhost:8080/h2-console), JDBC URL `jdbc:h2:file:./data/tododb`)에서 다음 SQL을 실행하여 평가용 데이터 12개를 넣는다.

```sql
INSERT INTO todo (title, memo, done) VALUES
  ('스프링 부트 설치', 'JDK와 Gradle 설치', TRUE),
  ('IoC와 DI 복습', NULL, TRUE),
  ('REST API 연습', 'GET, POST, PUT, DELETE', TRUE),
  ('JPA 엔티티 작성', NULL, FALSE),
  ('스프링 MVC 정리', '요청 처리 흐름', FALSE),
  ('Thymeleaf 문법 정리', NULL, TRUE),
  ('운동하기', '30분 걷기', FALSE),
  ('장보기', '우유, 계란, 두부', FALSE),
  ('스프링 시큐리티 예습', NULL, FALSE),
  ('책 읽기', NULL, TRUE),
  ('스프링 복습', '8장~11장 다시 읽기', FALSE),
  ('방 청소', NULL, FALSE);

SELECT COUNT(*) AS total, SUM(CASE WHEN done THEN 1 ELSE 0 END) AS done_count FROM todo;
```

> 결과: 전체 12개, 완료 5개. 제목에 "스프링"이 들어간 할 일은 4개(완료 1개, 진행 중 3개)이다.

### 2) 화면 확인 순서

| 순서 | 확인 내용 | 기능 |
| --- | --- | --- |
| 1 | 목록: 요약 문장("전체 12개 중 5개 완료"), 최근 등록 순, 상태 표시, 공통 헤더·푸터, 5개씩 표시 | F4, F9 |

### 3) REST API 확인

평가자는 다음 요청 파일(`http/todo-eval.http`)로 REST API를 확인한다. `{번호}`는 A3의 응답으로 받은 새 할 일의 번호로 바꾼다.

```http
@baseUrl = http://localhost:8080

### A1. 목록 → 200, 번호 내림차순
GET {{baseUrl}}/api/todos

### A2. 완료만 → 200, done: true만
GET {{baseUrl}}/api/todos?status=done

### A3. 등록 → 201, Location
POST {{baseUrl}}/api/todos
Content-Type: application/json

{
  "title": "API로 등록",
  "memo": "REST API 평가"
}

### A4. 제목 없이 등록 → 400
POST {{baseUrl}}/api/todos
Content-Type: application/json

{
  "title": "  ",
  "memo": "제목 없음"
}

### A5. 조회 → 200
GET {{baseUrl}}/api/todos/{번호}

### A6. 변경 (done 없음) → 200, done은 false 그대로
PUT {{baseUrl}}/api/todos/{번호}
Content-Type: application/json

{
  "title": "API로 변경",
  "memo": "변경한 메모"
}

### A7. 변경 (완료 처리) → 200, done: true
PUT {{baseUrl}}/api/todos/{번호}
Content-Type: application/json

{
  "title": "API로 변경",
  "memo": "변경한 메모",
  "done": true
}

### A8. 제목 없이 변경 → 400
PUT {{baseUrl}}/api/todos/{번호}
Content-Type: application/json

{
  "title": "",
  "memo": "제목 없음"
}

### A9. 없는 번호 조회 → 404
GET {{baseUrl}}/api/todos/9999

### A10. 없는 번호 변경 → 404
PUT {{baseUrl}}/api/todos/9999
Content-Type: application/json

{
  "title": "없는 할 일",
  "memo": ""
}

### A11. 삭제 → 204
DELETE {{baseUrl}}/api/todos/{번호}

### A12. 없는 번호 삭제 → 404
DELETE {{baseUrl}}/api/todos/9999

### A13. 잘못된 status → 400
GET {{baseUrl}}/api/todos?status=abc
```

| A1, A2, A5, A9, A13 | F10 |
| A3, A4, A6, A7, A8, A10, A11, A12 | F11 |

마지막으로 [http://localhost:8080/swagger-ui.html](http://localhost:8080/swagger-ui.html) 에서 API 목록과 실행을 확인한다. (F11)

## 권장 진행 순서

2시간 안에 모든 기능을 구현하려면 시간을 나누어 진행한다. **점수는 기능별로 매기므로**, 막히는 기능은 넘어가고 다음 기능을 먼저 구현한다.

| 시간 | 작업 | 참고 |
| --- | --- | --- |
| 0:00 ~ 0:15 | F1, F2 프로젝트 생성·실행, 설정, DDL, 엔티티, 리포지토리, 서비스 뼈대 | 1장, 6장, 8장 |
| 0:15 ~ 0:30 | F4 목록 화면, 공통 레이아웃 | 9장, 10장 |
| 0:30 ~ 1:00 | F3, F5, F6, F7 등록·상세·수정·완료 전환·삭제 | 11장 |
| 1:00 ~ 1:25 | F10, F11 REST API, Swagger UI | 5장, 8장 |
| 1:25 ~ 1:50 | F8, F9 검색·상태 필터·페이지 나누기 | 7장, 8장, 10장 |
| 1:50 ~ 2:00 | 전체 확인, 제출 | |

> F8과 F9는 난이도가 높으므로 뒤로 미루었다. 목록 조회를 처음부터 `Pageable`을 받는 서비스 메서드로 만들어 두면 나중에 고칠 코드가 줄어든다.

## 제출 방법

1. 애플리케이션을 종료한다.
2. 프로젝트 폴더에서 `build`, `data`, `.gradle` 폴더를 **삭제**한다.
3. 프로젝트 폴더를 압축하여 `이름_todo.zip`(예: `홍길동_todo.zip`)으로 제출한다.

> 제출 시간 이후에 제출한 파일은 평가하지 않는다. 완성하지 못한 기능이 있어도 **실행되는 상태**로 제출한다. 실행되지 않으면 **20점을 감점**한다. 제출하기 전에 반드시 `bootRun`으로 실행해 본다.
